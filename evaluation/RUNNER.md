# 外部电脑 Agent 执行与独立复核协议

## 0. 执行身份与权限

Codex、Claude Code 或其他具备电脑操作能力的应用均可运行。平台相关电脑技能、权限和用户授权优先；本说明不授予越权操作权限。不绑定某个坐标、API 或模型。桌面动作使用当前观察到的控件或坐标，每次动作后重新观察，失去窗口绑定时重新选择窗口。不可绕过系统对话框或权限限制来完成任务。

桌面代理轨道：通过真实屏幕、键鼠、可访问性控件执行，不调用私有 IPC、直接读写会话状态、注入 DOM 或读取评分文件帮助完成。开发用 Playwright 工程回归单独标记 `diagnostic`；其成功不能替代原生文件选择器、输入法或真人体感验证。

执行者只能看用户简报及环境准备者提供的启动信息；案例的 `must`、`observe`、底稿、正反例和评分器均不可提供给模拟用户。拥有仓库全部权限的同一个上下文即使不主动打开底稿，也不自动构成盲测。

## 1. 环境准备者

1. 校验套件；明确 development/holdout、桌面/诊断/语义轨道及 current/target。
2. 用 `prepare` 创建全新 staging，按 SETUP.md 执行案例特殊准备；只授权 staging/codex/sessions 与 archived_sessions。不得授权仓库、整个用户 .codex、答案目录、runner 产生日志或历史运行结果。
3. 给进程设置 launch-env.json 中的 `DOGDOG_USER_DATA` 和 `CODEX_HOME`；删除值为 null 的环境变量，而不是传入字符串 `null`。先校验新 profile 和专用 trace 根，再启动。
4. 配置本机 mock 服务或明确获准的真实服务。当前交付的试跑不使用真实密钥或付费模型。mock 各模式为受控行为脚本，不具有通用推理能力。
5. 记录实际 exe 路径、产品版本、exe 哈希及 app.asar 哈希（Electron exe 本身不足以识别业务代码）、源码 revision/未提交状态、模型/协议和配置指纹、分辨率/缩放、夹具哈希、开始时间。未知项写 null 并说明，不猜测。
6. 独立保存准备清单；向执行者只提供 brief、启动入口、可用测试服务和用户应知信息。真实数据未获授权时停止相关任务。

批量/异常夹具如有 `setup.json` 或生成脚本，只由准备者执行，完成后记录实际生成文件数与哈希。`prepare` 只复制现成 JSONL，不默默执行夹具中的脚本。变体先在独立新目录施加 change，再核对评分包中的 expectedDifference；不改源夹具。

## 2. 模拟用户

入口提示词：

> 你是 DogDog 的代理用户。只使用给定 brief 中的事实与允许回答；通过真实 UI 完成目标，不读取仓库、底稿、请求记录或存储文件。DogDog 追问时按 answers 的条件回答；未给定事实使用 unknownReply，不能为了让任务成功而发明背景。记录动作、输入、可见结果、时间和关键截图。遇到问题保留首次失败，不修复产品，不自行调整验收标准。达到回合/时间预算后停止并提交过程证据，不自行宣布最终通过。

多轮任务按条件回应，不要求固定逐字问法。不得告知 DogDog 本来应自行检索到的文件、来源 ID、答案或正确工具序列。允许任务指定的正常纠正和补充事实。纯桌面任务失败后，可以移交独立诊断上下文；诊断者的绕行成功不改写桌面结果。

## 3. 审查员

独立新上下文收到 reviewer 包及本轮过程证据后：

1. 先核对输入、环境和版本有效性，排除读到答案、检索污染、错误版本和缺失证据。
2. 逐条读取事实底稿、反证和未知项；核对引用实际支持哪条结论，不仅检查引用存在。
3. 逐条记录检查与评分：规则 ID、观察、证据文件位置、判定、理由及不确定性。不得以被测模型自述完成作唯一证据。
4. 按 SCORING.md 分类；独立保留产品问题、未实现目标、环境问题、评分问题。疑难判 `grading_dispute`，不要强行投票制造确定性。
5. 输出结果 JSON 和 review.md。结果收集者运行 `validate-run`；通过只表示契约完整，并不自动证明语义评分正确。

入口提示词：

> 你是独立审查 Agent。根据案例规则、原始夹具和运行证据评估，接受不同但有效的措辞及工具路径。检查自己的评分依据，若运行记录不足就写不足，若评分规则错误就列争议。使用三级锚点逐维评分；不得从代理用户接受建议推断真实收益。

## 4. mock 服务与请求观测

启动：`node evaluation/tools/mock-service.mjs --out <新目录> --mode <模式> [--port 0] [--text <合成回答>]`。

| 模式              | 行为                                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| text / fragmented | 指定文本正常完成；fragmented 分成小字节块                                                                                 |
| auto              | 固定启动问题演示：discover、search、读取 S1/S2、引用；仅适用于约定夹具                                                    |
| script            | 准备者通过/control传入stages，每阶段包含text或tools数组（name/args/id），按请求依次返回；可用于任意合成夹具的传输边界验证 |
| ask               | 首次 ask_user，回答后继续                                                                                                 |
| slow / disconnect | 保持未完成流；或有部分文本但无完成事件结束                                                                                |
| bad-citation      | 返回不存在的 S99:L999                                                                                                     |
| http401 / http503 | 返回含合成错误标记的失败                                                                                                  |
| redirect          | 302 指向同一本机服务的拒绝路径，检查客户端不跟随                                                                          |

准备者可 POST `/control`，JSON `{ "mode": "ask" }`，重置脚本阶段；也可设置 text。此接口属于测试服务，不是 DogDog 用户接口。不要用它替执行用户补事实。发送次数以 `requests.jsonl` 为准，不能只看 UI；未经授权零发送需比较明确时间边界内的计数。服务切换对比凭据摘要，不将真实密钥写到证据里。

## 5. 结果、重跑与版本比较

每次独立 trial 保存：`manifest.json`、`events.jsonl`、`result.json`、`review.md`、截图和必要请求/状态审计。记录 fixtureHashes、配置、步骤和终止状态，所有证据使用相对于 run 根的路径。示例见 templates/；不把填空模板当实际运行结果。

同一案例重复3次用于未来真实模型关键基线，保留首次结果和所有重试；不得“跑到成功为止”。成本未知写 null，不把未知费用写成0。mock 的模型账单为0，操作 Agent 自身费用不在此账单内。

比较时固定案例版本、划分、夹具、服务/模型、协议和显示条件。按体系及 current/target 展示通过/失败/未运行/未实现分母、逐维分数、耗时和请求数，链接退化案例。不同条件的结果单列，不做无依据提升百分比。

独立验收集一旦被用于调优或向开发者逐例揭示答案，即失去该轮保留资格；后续版本把这些场景迁入开发回归并补足新的独立家族。该调整必须版本化，不能静默换题。
